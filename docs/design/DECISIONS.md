# Design decisions

The history of the rules in `docs/design/DESIGN_SYSTEM.md`: what was decided, when, what it replaced, and where it landed. Append only; correct an entry with a new one. This file holds no rules: where it and DESIGN_SYSTEM.md differ, DESIGN_SYSTEM.md wins. The principles and their cases are in `docs/design/PRINCIPLES.md`.

## 2026-11

- **11-10 Structure rules for primary screens** (#3186): sessions that need the user, the work-item row and list controls (3.4), pending requests (4.8), objects, titles and state words (5.6), a reading route, and who looks at a UI change (1.4). They hold on iOS, Android and web; visual values stay per platform. They apply `docs/design/PRINCIPLES.md` to Agent work rather than adding principles. Rejected: five more principles next to those six; rules for the Apple apps only.
- **11-10 Default views stay as they are** (#3186): the rules do not choose a default grouping. iOS and Android open on By Repository; the web opens on its paged list, on By to-do, or on the chat-list view (#2805). Rejected: attention sections as the default on every platform.
- **11-10 Rows may show the model's short name** (#2805, #3186): raw model IDs stay off primary screens. Rejected: no model in rows.
- **11-10 List controls follow #2805** (#3186): a grouping control, status chips and a filter bar may sit above a list, each kind looking like itself. Rejected: one row of filter chips, with grouping and display in the ⋯ menu.
- **11-10 Awaiting Reply stays its own state** (#3186). Rejected: folding it into Needs You.
- **11-10 No freeze on new appearance options** (#3186): revisit once the structure rules have been in use for a while. Rejected: freezing new styles now. Where: 1.2.
- **11-10 Row content, not a new row style** (#3186): every row style shows the work-item row's content, with the Avatar style's look as the reference. Rejected: a fourth row style. Where: 3.4.
- **11-10 Answers stay in rows** (#3186): choices, and low-risk tool approvals whose full command is shown. Plans, high-risk actions and Always Allow for This Session open the session. Rejected: opening the session for every answer. Where: 3.4, 4.8.
- **11-10 An Agent's run is called a session** (#3186). Rejected: "task", which names the work Persona hands out. Where: 5.5, 5.6.
- **11-10 Needs You counts sessions** (#3186): a row is a session, so the number equals the rows (principle 4). Rejected: counting requests. Where: 4.8.
- **11-10 No failed state** (#3186): a failed run says what failed in its row. Rejected: a failed state with its own priority. Where: 5.6.
- **11-10 Who looks at a UI change** (#3186): a person for a large change, the Agent itself for a small one. Rejected: always a person; always the Agent. Where: 1.4.
- **11-10 By Repository keeps its tree** (#3186): computer, repository, worktree, then session. Rejected: the work-item row in By Repository, which would leave the old view nowhere to be found. Where: 3.4.
- **11-10 By Repository draws the work-item row** (#3753, a tester's decision on iOS): its structure stays (computer, repository card, worktree lines), its sessions are the display's rows as in every other grouping, and every row, heading and fold control in the Agents list is at least 44 pt. Replaces the rows of "By Repository keeps its tree" (#3186) and #3182's one-line rows; the Mac's cards are unchanged. Rejected: one-line rows in By Repository alone (one line per agent is Compact List, in every grouping). Where: 3.4, 6.3.
- **11-11 One wording for request titles** (#3690): every client takes the words iOS used ("Plan awaiting approval", "Needs your permission", "{agent} has a question", "Terminal needs you"), in en, zh-Hans and ja. Rejected: titles that say the action ("Wants to run a command", Android's). Where: 4.8, 5.6.
- **11-11 Persona chats are the main chat and 常驻 only** (#4331): the sidebar's Persona chats show the main conversation and the leaders, called 常驻 (en "Pinned") on every client, each with what it has Working and Waiting on you (the direction tree's counts, #4352); every other chat is under All chats. Pinning a chat is making it a leader (设为常驻 / 取消常驻, the hub's `directions/{id}/make` / `end`), so there is one kind of pin, the same on every device. Rejected: per-device pins next to leaders; a separate Make it a direction action; Other chats with the latest 5. Where: `docs/web/web.md`, `docs/apple/ios.md`, `docs/android/android.md`.
- **11-11 Needs You is blue on every client** (#4194): the color iOS shows today. Rejected: red, recorded for the chat top bar on 11-06 but never used in code; the web's amber. Where: 2.1.
- **11-11 Android takes the iOS contrast floors** (#4194): links 3:1, white on accent 3.5:1, bubble text 4.5:1, with the iOS color values; Android Glass draws the iPhone's colors as they are. Rejected: 4.5:1 for all Android text. Where: 6.
- **11-11 One hub-built direction tree** (#4352): each direction (leader conversation) opens into its open tasks with a state (在做 / 等你 / 卡住 / 待验收), each task into its Agents and their sub-Agents; the sidebar, the To-dos grouping and the Agents grouping on every client read `GET /api/v1/assistant/directions/tree` and never group or judge state themselves. Tasks with no supervisor or the main chat's go to a 书记官 group; a direction row shows only 「在做 N · 等你 N」; the group is called 常驻 to the owner. Rejected: each client grouping `GET /api/v1/todos` by supervisor (three copies of the state rule); a worker task listed beside its leader's (it shows under the leader's Agent instead). Where: `docs/assistant/unified-entry.md` "The direction tree".
- **11-11 One feedback layer on Android** (#4194): one toast, modeled on iOS, for all in-app feedback: error, success or info, one slot per window, 2.5 / 4 / 5 s, from the top. Rejected: a Snackbar, per-page hosts and system toasts side by side. Where: 4.3.
- **11-12 Recent comes back under 常驻** (#4873, correcting the 11-11 entry for #4331): with only the main chat and 常驻 listed, every chat the owner had just been in sat behind All chats, one more tap each time. Persona chats are now the main chat, 常驻, then Recent (the 5 most recently active conversations that are neither main nor 常驻 and that the user opened; those Persona opened by itself stay in All chats; no heading when there are none), then All chats. Still rejected: per-device pins, the Other chats heading, the Automatic row. Where: `docs/web/web.md`; iOS (`docs/apple/ios.md`) in its own PR for #4873, Android in #4922, with the same rule.
- **11-12 A Persona conversation's own cards are in its chat** (#4883): above the composer on iOS, Android and the web, as an Agent's are; Needs you counts them and its row closes the tray onto the card. Replaces the web's and Android's own cards inside the closed Needs you tray (#3387). Rejected: opening the tray by itself when a card comes (it covers the chat and still hides the card behind a tap once closed). Where: 4.8.
- **11-12 Tool approvals say "Waiting for your approval"** (#4883): 在等你批准 / 承認を待っています on cards and rows, "{agent} is waiting for your approval" with a name, on every client. Replaces "Needs your permission" from 11-11 (#3690) for cards and rows; notification titles keep it for now. Where: 5.6.
- **11-12 Providers are named by their display name** (#5029): every web place that names a model provider or launcher leads with its display name and shows the startup ID as secondary text; custom gateways are added with a display name in any language and the hub makes up the ID. Rejected: one field that is both name and ID (it rejected anything but ASCII); a renamable ID (launches, Agent presets and the model settings refer to it). Where: "Provider display names (#5029)".
- **11-12 Clear context clears the main chat in place, without asking** (#5095, the user's alignment with Cindy's `/clear`): `/clear` and **Clear context** in the ⋯ menu run at once; the chat empties where it is and the composer stays at the bottom; the old chat is archived, not deleted. Rejected: a confirmation (nothing is lost); an Undo toast (Cindy shows none; the archived chat is the way back); landing on the centered new-chat page (the layout jump Cindy removed). Where: 4.4.
- **11-12 New Agent picks a model, not a launcher** (#5104): New Agent's model choice is the chat's model pill and unified model panel; the launcher and its engine follow from the model picked and the engine stays visible; Model settings' default is a follow row on top and the profile's presets a group of their own. Replaces the Preset, Launcher, Model and Thinking effort fields. Rejected: keeping the launcher chips beside the pill (two places to choose one thing); presets as favorites (they are the profile's, not the user's copies). Where: "New Agent's model choice (#5104)".
- **11-12 The web's Recent lists 15, a setting, with Show more** (#5146, extending the 11-12 entry for #4873): five left most of the chats the owner had just been in behind All chats on a desktop-sized sidebar. Persona chats › Recent lists 15 by default; Settings › General › Appearance chooses 5 / 10 / 15 / 25 for this browser, and Show more adds as many again until none are left, kept across reloads. iOS and Android keep 5 for now. Where: `docs/web/web.md`.
- **11-12 A herdr tab's workers live in the lead's Team panel** (#5180, the owner's alignment with cindy's Team): in a tab whose first pane is an Agent, that Agent is the lead and the tab's other running Agents are its workers. A worker is never a row or count of its own; the lead's row carries its state, and the lead's page has a Team side panel with the workers' strip and the shown worker's conversation, opening by itself with cindy's timing (wide screens only). Replaces the pane tabs strip over the chat (#2320) and a row per pane. Rejected: keeping the strip next to the panel; cindy's "closing the Team tab ends the team", which has no herdr equivalent. Where: 3.3, 3.4, 4.8.
- **11-12 By Repository's repository card and worktree lines are iOS's on Android's Glass** (#4338 A7): each repository a card whose header has the folder, the bold name and the chevron, no counts, its actions in its long press; each worktree a line with Primary on the main checkout, the branch when the name is not it or Detached HEAD as a caution, "N agents" or Idle, dimmed while its computer is offline. Replaces Android's plain repository and worktree headings with state counts, marks and a ⋯ on Glass; Brief and Board keep theirs (alignment decision 8). Android takes the branch, Detached HEAD and offline from the node's git place and the computer until it has the workspace catalog iOS reads them from. Rejected: the one-line tree row the plan asked for (A2), which iOS has dropped (the 11-10 entry for #3753). Where: 3.4.
